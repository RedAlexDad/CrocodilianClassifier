## Анализ

### 1. AdamW vs Adam vs SGD

**AdamW 50ep (0.905)** победил **Adam 50ep (0.900)**, хотя разница небольшая (~0.5 п.п.).
В 20-эпохных запусках, напротив, **SGD (0.877)** обошёл **Adam (0.803)** и **AdamW (0.749)**.

**Почему AdamW выиграл на 50 эпохах:**

- AdamW добавляет weight decay, который не интерферирует с адаптивным LR (в отличие от Adam + L2).
- При малом LR (0.0005) и большом числе эпох Weight Decay эффективно подавляет переобучение, не замедляя сходимость.
- Precision вырос до 0.920 — модель реже ошибается с ложными срабатываниями.

**Почему SGD выиграл на 20 эпохах:**

- У SGD был в 10 раз больший LR (0.01 против 0.001 у Adam/AdamW).
- При 20 эпохах модель не успевает насытиться — высокий LR SGD даёт быстрый прогресс.
- На 50 эпохах с LR=0.0005 SGD застрял (0.685) — слишком малый шаг для SGD-сходимости.

**AdamW 20ep (0.749) — худший среди 20-эпохных:**

- LR=0.001 — возможно, занижен для AdamW при 20 эпохах. Weight decay не успел отработать, а шаг был мал.

### 2. Влияние числа эпох

| Оптимизатор | 20ep  | 50ep  | delta  |
| ----------- | ----- | ----- | ------ |
| Adam        | 0.803 | 0.900 | +0.097 |
| SGD         | 0.877 | 0.685 | −0.192 |
| AdamW       | 0.749 | 0.905 | +0.156 |

- **Adam и AdamW** значительно выигрывают от увеличения числа эпох (+0.10 и +0.16 mAP).
- **SGD** с 50 эпохами при LR=0.0005 деградировал — не хватило шага для выхода из локального минимума.
- Вывод: для адаптивных оптимизаторов (Adam/AdamW) 50 эпох оправданы; для SGD нужен более высокий LR или LR scheduler.

### 3. Слабое место — класс Crocodile

Лучшая модель (AdamW 50ep):

- **Crocodile:** mAP50 = 0.816, Recall = 0.500
- **Alligator:** mAP50 = 0.921, Recall = 0.700
- **Cayman:** mAP50 = 0.979, Recall = 0.917

**Crocodile стабильно слабее во всех 6 запусках.** Причины:

1. **Дисбаланс данных:** cayman (136), crocodile (88), alligator (74).
2. **Визуальное разнообразие:** крокодилы сильнее отличаются по форме морды, текстуре, окраске.
3. **Recall = 0.500** — модель пропускает половину крокодилов на изображениях. Вероятно, нужна аугментация, больше данных или weighting классов.

Интересно: у **Alligator** recall вырос с 0.813 (Adam 20ep) до 0.700 (AdamW 50ep), хотя mAP50 вырос — то есть модель стала точнее, но менее чувствительной. Это типично при росте precision за счёт recall.

### 4. Mask mAP vs Box mAP

Во всех запусках **mask mAP = box mAP** — это особенность YOLOv8-seg: маска оценивается только если bbox правильный. Маски сегментации не улучшают и не ухудшают детекцию.

При этом **Mask mAP50-95** (0.817) лишь незначительно ниже Box mAP50-95 (0.832) — маски ложатся качественно, без сильного проигрыша.

### 5. Почему выбрана AdamW 50ep для продакшена

| Критерий  | Adam 50ep | AdamW 50ep |
| --------- | --------- | ---------- |
| mAP50     | 0.900     | **0.905**  |
| mAP50-95  | 0.817     | **0.832**  |
| Precision | 0.886     | **0.920**  |
| Recall    | **0.832** | 0.706      |

- **Precision 0.920** — решающий фактор для пользовательского сценария: меньше ложных срабатываний при классификации.
- Более высокая mAP50-95 (0.832) говорит о лучшей локализации.
- Recall 0.706 компенсируется тем, что на типичном изображении 1-2 объекта, а не сцена плотного скопления.

### Вывод

**AdamW + 50 эпох + LR=0.0005** — оптимальная конфигурация для данного датасета. Для улучшения crocodile-класса потребуется сбор дополнительных данных или применение Class-Balanced Loss / Focal Loss.

## CLIP-поиск карточек (дополнительное задание ДЗ2)

### Проблема: одинаковые проценты похожести

При первом запуске CLIP-поиска все 36 карточек получали ~24% сходства,
независимо от входного изображения. **Причина:** `openai/clip-vit-base-patch32`
обучена **только на английском языке**. Русские описания карточек CLIP
воспринимала как неразличимый шум — все текстовые эмбеддинги были
практически одинаковы, и cosine similarity давал равномерное распределение.

### Решение

1. Переведены все 36 описаний карточек на английский язык
2. Каждое описание расширено визуальными деталями (цвет, текстура, поза, среда)
   для более контрастных эмбеддингов
3. Русские названия карточек (`title`) сохранены для UI, в эмбеддинге
   участвует только английское `description`

### Результат после исправления

| #   | Карточка                       | % сходства |
| --- | ------------------------------ | ---------- |
| 1   | Кубинский крокодил             | 31.2       |
| 2   | Аллигатор с распахнутой пастью | 30.9       |
| 3   | Аллигатор в зоопарке           | 30.4       |
| 4   | Китайский аллигатор            | 30.4       |
| 5   | Аллигатор с детёнышами         | 30.1       |

**4/5 top результатов — правильный класс.** Разброс 30.1–31.2% (было 24% у всех).
Ограничение: все крокодиловые визуально похожи, поэтому CLIP даёт
близкие scores даже для разных видов.

### Проблема 2: CLIP путает классы на крупных изображениях

При crop-е из больших исходников (e.g. 4000×3000) размер канваса получался
огромным — PNG dataUrl превышал `DATA_UPLOAD_MAX_MEMORY_SIZE` (10 MB),
и Django возвращал 500.

**Исправление:**

1. `canvasToDataUrl` — переключён с PNG на JPEG (0.85). JPEG для фото
   в 5–10× компактнее PNG.
2. `cropDetection` — ресайз crop-канваса до max 640px по длинной стороне.

### Проблема 3: CLIP не различает виды крокодиловых

CLIP (`openai/clip-vit-base-patch32`) обучен на общих интернет-изображениях.
Для него все крокодиловые — «зелёное чешуйчатое в воде», поэтому top-5
результатов часто содержал карточки других классов (e.g. кайман → нильский крокодил).

**Исправление:** `search_similar_cards` принимает `class_id` от YOLO-сегментации
(mAP50=0.905) и ранжирует только среди 12 карточек соответствующего класса.

**Пример:** кайман_0010.jpeg → YOLO class_id=1 (cayman) → CLIP ищет среди 12
карточек кайманов:

| #   | Карточка                | % сходства |
| --- | ----------------------- | ---------- |
| 1   | Кайман крокодиловый     | 32.2       |
| 2   | Чёрный кайман           | 32.1       |
| 3   | Кайман с широкой мордой | 31.4       |
| 4   | Кайман в сезон дождей   | 30.9       |
| 5   | Кайман в мутной воде    | 30.8       |

**5/5 — правильный класс.**
